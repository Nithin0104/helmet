# Home Page — Principal QA Review

*Lens: automated test coverage, edge cases, accessibility, responsive behaviour.*
Findings Q1–Q7. See [`README.md`](./README.md) for the ranked matrix.

## Executive read

The suite is genuinely strong **everywhere except the page layer**: all 29 primitives, all
12 composites, both contexts, all hooks, `lib/*`, and three data contracts have co-located
tests, most paired with a `vitest-axe` `toHaveNoViolations()` check, plus a cart-flow and a
routing integration test. Coverage thresholds are enforced (lines/functions/statements 70,
branches 65 — `vite.config.ts:29`).

The gap is the **home page itself**: none of its eight sections has a behavioural test
(only incidental H1 coverage from the routing integration test), and `home.ts` is the one
data module with no contract guard. Several `phase-3-home.md` "Verify" items (edge cases,
accent switch, reduced motion, responsive) have no automated or recorded manual coverage.

---

## Q1 · High · M — No section-level tests for Home

**Problem.** The eight home sections have **no co-located test** — a documented blocker
(`CLAUDE.md`: "If a test case doesn't already exist for the component… you're touching,
write one before considering the work done"). They're exercised only indirectly by
`tests/integration/routing.test.tsx`, which asserts the hero H1 and nothing about the
sections' actual output.

**Evidence.** No `*.test.tsx` exists for any of:
`src/pages/HomePage/sections/{HomeHero, StatBar, CategoryStrip, WhyUs, CompareBand,
ShowroomCta, ReviewsMarquee, Reveal}.tsx` (confirmed against the full test inventory — every
other tier is covered). `HomePage.tsx` itself is untested beyond the route render.

**Solution.** Add co-located tests, following the existing composite test patterns and the
shared `tests/utils/renderWithProviders` helper:
- **Per section:** renders its heading/accessible name; `vitest-axe` `toHaveNoViolations()`.
- **CategoryStrip:** renders one `CategoryCard` per `CATEGORIES` entry with the correct
  `href` and accessible name.
- **HomeHero:** renders the `h1`, the badge, and both CTAs with their expected `to` targets;
  `StatBar` renders one stat per `STATS` entry.
- **ReviewsMarquee:** renders one card per review and passes the **real** rating (guards
  **F1**), not a hardcoded 5.
- **WhyUs / CompareBand / ShowroomCta:** render all data-driven items and the section
  landmark (`aria-labelledby`).

**Verify.** `npm test` green; `npm run coverage` still meets thresholds (these sections
currently ride on incidental coverage — real tests make that robust).

## Q2 · Med · S — No `home.ts` contract test

**Problem.** `home.ts` is the only `src/data/*` module without a contract guard; content
edits or a future API swap could ship a broken shape undetected. `products.ts`,
`accessories.ts`, and `navigation.ts` all have one.

**Evidence.** `tests/contracts/` contains `data`, `accessories`, `navigation` contracts —
no `home` contract.

**Solution.** Add `tests/contracts/home.contract.test.ts` asserting:
- `HERO` has non-empty `badge`/headline parts/`copy` and `primary`/`secondary` CTAs with
  `/`-rooted `href`s.
- `STATS` non-empty; each has numeric `value`, a `label`, valid `decimals`/`suffix`.
- `CATEGORIES` non-empty; each has `kicker`/`title`/`caption` and a `/`-rooted `href`.
- `WHY_US` non-empty; each has `icon`/`title`/`body`.
- `COMPARE` / `SHOWROOM` fields non-empty; CTA `href`s `/`-rooted.
- `HOME_REVIEWS` non-empty; each has `quote`/`name`/`model` and (after **F1**) a
  `rating` in 0–5.
- `STORE_RATING` typed consistently (guards **F2**).

**Verify.** The contract fails if any field is missing/mistyped — the same safety net the
other data modules have.

## Q3 · Med · S — Edge / overflow cases untested

**Problem.** `phase-3-home.md` "Edge/responsive" calls out cases that have no automated
coverage at the page level.

**Evidence & cases.**
- **Empty rail:** if `getBestsellers`/`getNewArrivals` return empty, `ProductRail` shows its
  empty state (`ProductRail.tsx:100`). The empty branch is unit-tested on the component;
  there's no home-level test that the rails degrade gracefully.
- **Long product names** wrapping in cards without breaking the track height.
- **Long review text** not inflating the marquee row height / breaking the loop.

**Solution.** Add targeted tests: feed a `ProductRail` an empty tab and assert the empty
message (home context); render a `ProductCard`/`ReviewCard` with an overlong
name/quote fixture and assert it stays within its container (or add these to the manual
checklist below if layout assertions are impractical in jsdom).

**Verify.** Empty and overflow inputs render without layout breakage.

## Q4 · Med · Browser — Accent switch (all 4 presets)

**Problem.** The accent theming is the design's signature; it needs a real recolor pass
(jsdom can't verify computed colors). Not currently recorded anywhere.

**Checklist (run via the `/run` skill, toggling red/blue/orange/purple):**
- Hero badge background + "30% off" highlight recolor.
- Hero primary CTA + showroom "Get directions" recolor (and hover shadow).
- Rail active tab fill; category card arrow; "SEE ALL"/"ALL" links.
- Compare tile **B** border/label; compare link underline.
- Ambient glow tint (ties to **D3**).
- **Gold review stars stay gold** (intentional — verify they do *not* take the accent).
- No stale color anywhere after switching.

**Verify.** Every accent-bound surface updates; the gold rating color is deliberately
accent-independent.

## Q5 · Med · Browser — Reduced motion

**Problem.** Need to confirm all looping/entrance motion actually stops under
`prefers-reduced-motion`.

**Evidence.** `src/styles/global.css:230-239` neutralizes animations/transitions globally;
`CountUp` and `useReveal` additionally gate on the media query in JS.

**Checklist (emulate reduced motion in DevTools):**
- Hero `fadeUp` entrance and `.hero`/`.store` sweep shimmer stop.
- Reviews marquee stops (or doesn't auto-scroll).
- Glow pulse stops.
- `CountUp` jumps to final value (no tween); reveal shows final state immediately.

**Verify.** No perceptible motion with the setting on; content fully visible/usable.

## Q6 · Low · Browser — Keyboard pass

**Checklist.**
- Tab order is logical top→bottom; every CTA, rail tab, category card, and product card is
  reachable and operable.
- Rail tabs: Arrow Left/Right switches Bestsellers/New Arrivals (unit-tested in
  `ProductRail.test.tsx`); Tab moves into the track/cards.
- **Focus is visible on every element** — currently blocked by **D8**; re-run after D8 lands.
- (No modals/sheets on the home, so Escape handling is N/A here.)

**Verify.** A mouse-free traversal of the whole page is possible and legible.

## Q7 · Low · Browser — Responsive

**Checklist (widths 320 / 375 / 768 / 1280).**
- No horizontal **body** scroll at any width.
- Category grid: 1 col → 2 (`≥640`) → 4 (`≥1000`).
- Hero aspect-ratio: 3:4 → 4:3 (`≥480`) → 16:7 (`≥700`, min-height 440).
- Showroom aspect-ratio: 4:5 → 3:2 (`≥480`) → 2.6:1 (`≥700`).
- Rails: if kept as shelves (**D1**), horizontal scroll is contained to the track, not the
  body; if switched to grid, cards wrap cleanly.
- Compare band: fixed 260px visual doesn't crowd text at ~280–320px (it wraps as intended).

**Verify.** Clean layout at mobile / tablet / desktop; no clipped or overlapping content.
